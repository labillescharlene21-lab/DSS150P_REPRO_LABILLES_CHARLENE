# Reproducibility report

**Project:** reproducible rebuild of the group project *"Strengthening Philippine Stroke Care: A Machine
Learning-Based Stroke Risk Assessment"* (Abad, Labilles, Tumaneng; DSS141P).
**Scope reproduced:** the paper's best model: XGBoost on the hybrid feature set including VAAF and TGI
(paper section 3.1.4.3, AUC-ROC 0.7500). The paper's other experiments (SVM, CNN, Random Forest, Logistic
Regression, SMOTE/undersampling/ensembles) are out of scope for this laboratory.

> Numbers below are from the reference run. `docs/metrics_comparison.md`, `docs/diagnosis_results.md` and
> `docs/acceptance_report.md` are regenerated by the pipeline and are the authoritative, current values.

## 1. Verdict

**Reproduction succeeds.** The pipeline rebuilds the model-ready dataset from the original source file and
retrains the model from it. Reproduced ROC-AUC is **0.75004** against the baseline **0.7500**
(difference 0.00004, declared tolerance 0.001). The train and test rows are the *same logical rows* as the
baseline: the SHA-256 of the sorted train and test ids equals the hashes derived from the group's own split.
The curated dataset equals the group's `Stroke_Prediction_Engineered2.csv` in all 3,265 rows and 18 columns.

## 3. Engineering gaps found in the prior project, and the treatment

| Current behavior | Risk | DSS150P concept | Remediation |
|---|---|---|---|
| Colab notebooks read `/content/...` paths | cannot run elsewhere | reproducible environments | relative, configured paths (`config/settings.yml`, `.env`); no absolute paths (acceptance test A3) |
| Three notebooks chained through intermediate CSVs (`Cleaned_Inspected` to `Engineered2`) | hidden state, order dependence | modular code, ETL | `ingest`, `transform`, `curate` functions with one CLI; raw, staging, curated layers |
| Cleaning rules only in notebook code (gender "Other" to mode, children "Unknown" smoking, BMI median) | not repeatable or testable | transformations, quality | unit-tested staging code; quarantine for invalid rows |
| Dataset identity not recorded | cannot prove which file was used | source systems, contracts | SHA-256 in `source_manifest.yml`, checked on every run; `data_contract.yml` |
| Library versions not recorded or pinned | results change silently (**measured**: xgboost below 3.3.0 gives 0.75087 not 0.75004) | reproducible environments | `requirements.txt` pins, Docker images, acceptance test A5 rejects older XGBoost |
| Split performed twice; class weight taken from a different split than the one trained on | easy to miss; changes the result | predictive reproducibility | both steps coded and documented; `split_manifest.json` with id hashes |
| Paper's hyperparameters (183 trees, 0.029) differ from the notebook's (250, 0.02, depth 2) | wrong parameters reproduce a different number | baseline capture | notebook values used and recorded in `expected_metrics.json` |
| Paper states "no null values"; raw data has 201 null BMI | undocumented imputation | profiling, contracts | profiled, contracted (`bmi` nullable, 5% limit), imputation in staging with counts logged |
| Metrics visible only in notebook output | no machine-readable result | observability | `metrics.json`, `reproducibility_check.json`, automatic comparison with tolerance |
| Row order determines the random split | reordering silently changes the result | determinism | curated sorted by `source_row_seq`; a check fails if order changes |
| No automated tests | regressions unnoticed | quality, testing | 50+ tests; 37 named data-quality checks; failure-injection tests |

## 4. Deterministic controls

Fixed data (checksummed source, deterministic batches, row hash), fixed code (Git, modular functions), fixed
dependencies (`requirements.txt`, Docker), fixed preprocessing (staging and curated rules in code, ordered by source
row), fixed split (`random_state` 42, manifest of id hashes), fixed hyperparameters (`config/settings.yml`),
fixed seeds (`random`, NumPy and XGBoost seeded from one value in `.env`/settings), and an automatic comparison
against the baseline on every run (`repro-check`).

| ROC-AUC | 0.7500 | 0.75004 | within tolerance (diff 0.00004) |
| Test rows / positives | 653 / 63 | 653 / 63 | match |

The baseline is quoted to four decimals, and 0.75004 rounds to 0.7500, so the 0.00004 "difference" is most
plausibly just the rounding of the published value: data, rows, split and parameters are identical, and no
measurable difference remains.

## 6. Diagnosis: what could change the metric (`python -m src.cli diagnose`)

Each experiment changes exactly one factor from the reproduced configuration (full table: `docs/diagnosis_results.md`).

| Factor changed | Effect on AUC (reference run) | Pinned by |
|---|---|---|
| Data | none: identical to the group's file | source checksum, contract, tests |
| Split rows | different split seed: +0.012; stratified split: -0.072; sorting by id: +0.012 | split manifest, `source_row_seq` order |
| Model seed | -0.005 | seed in settings |
| Class-weight origin | +0.001 (final train set instead of earlier split) | documented, coded |
| Hyperparameters | paper's table values: -0.001; depth 3: -0.020 | `settings.yml` |
| Feature set | dropping VAAF and TGI: +0.004 | feature list |
| Library | xgboost 2.1.4 to 3.2.0: 0.75087; 3.3.0 and later: 0.75004 (scikit-learn 1.7.2 vs 1.8.0: no effect) | pinned in `requirements.txt` |
| Platform / build | Windows 0.74653 (1 thread), 0.74119 to 0.74183 (2 to 4 threads) vs Linux 0.75004 | Docker (Linux) as the reference environment; `n_jobs: 1`; platform-aware tolerance |

**Diagnosis procedure if a future run differs:** (1) data identity and split hashes, then (2) preprocessing,
(3) split, (4) hyperparameters, (5) seeds, (6) library versions, (7) platform and threads. The first factor that
moves the metric by more than the tolerance is the cause.

## 7. Deviations from the prior project

1. Cleaning and feature rules were re-implemented as modular, tested code; behavior is unchanged and verified
   identical to the group's engineered file.
2. Hyperparameters follow the notebook, not the paper's table (the table's values give 0.74939).
3. The baseline's two-step split (class weight from an earlier stratified split) is preserved deliberately.
4. The BMI median is computed before the train/test split, as in the baseline (see limitations).
5. Audit columns (run id, hash, timestamps) and strict ordering by source row were added; they do not change the model input.
6. Only the final XGBoost model is reproduced, not the paper's other models.
7. XGBoost is pinned to 3.3.0 or newer, which the baseline's unrecorded environment evidently matched.

## 8. Known limitations

- **Single split, small test set.** With 63 stroke cases in the test set, a bootstrap 95% confidence interval for
  the reproduced AUC is about 0.687 to 0.814, and repeating the whole procedure over 20 seeds gives mean 0.761,
  standard deviation 0.037, range 0.699 to 0.826. Reproducing 0.7500 therefore means reproducing one specific split;
  it is not evidence of a stable 0.75.
- **Observation about the original study (not a pipeline defect).** The paper reports AUC 0.6963 and 0.7026 for
  earlier XGBoost models and 0.7500 after adding VAAF and TGI. That 0.05 difference is well within the split-to-split
  variation measured above, and on the identical split, removing VAAF and TGI gave 0.7535. The data do not show that
  these two features improve discrimination. A fair comparison needs repeated or cross-validated splits.
- **Mild preprocessing leakage.** BMI median imputation uses all rows before the split. It is kept to reproduce the
  baseline; a leakage-free version would fit the median on the training set only.
- **Platform sensitivity (measured).** With identical data, identical split rows (id hashes match) and identical
  parameters, the same XGBoost 3.4.1 gives AUC 0.75004 on Linux at every thread count, but on Windows 10 (AMD64,
  Python 3.12.4, 4 cores) it gives 0.74653 with 1 thread, 0.74119 with 2 and 0.74183 with 4 or the default.
  The baseline came from Google Colab (Linux). I did not investigate the mechanism; the Windows and Linux builds
  are not bit-identical. Therefore: the Linux Docker image is the reference environment and must match within
  0.001; other platforms are allowed up to 0.01 (the brief's recommended maximum), are reported as
  `pass_relaxed_tolerance`, and never relax the exact split checks. The thread count is pinned (`n_jobs: 1`).
  across CPU architectures and operating systems was not verified.
- **Static dataset.** Incremental ingestion is a laboratory simulation over fixed-order batches, not a business watermark.
- **Deployment scope.** Airflow runs in single-container `standalone` mode with no login; PostgreSQL loading in the
  benchmark uses INSERT rather than `COPY`. These are lab choices, not production designs.
- **Clinical validity.** The model is a methodological demonstration on a public dataset, not a validated clinical tool.
